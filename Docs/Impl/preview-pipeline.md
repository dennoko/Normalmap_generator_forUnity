# プレビューパイプライン実装メモ

`overview.md` は Python 実装からの**移植時**の仕様書です。プレビューの高解像度化にあたって
パイプラインを作り直したため、現行の挙動はこの文書が正となります。

---

## 1. 解像度の決定

```
作業解像度 = min(元画像の解像度, 上限)      上限 = 1024 / 2048 / 4096（既定 2048）
```

- **ウィンドウサイズには依存しない。** 旧実装は `position.width * 0.5` を解像度にしていたため、
  最小ウィンドウ（560px）では実質 280px しか出ておらず、さらにウィンドウ幅が 1px 変わるたびに
  全パイプラインを再計算していた。
- 元画像が上限以下なら `scale = 1` になり、`ScaleForPreview` が恒等写像になる。
  プレビューと保存出力が**同一の `Run()` を同一パラメータで通る**ので結果は完全に一致する。
- 縮小は `Binarize` カーネルに統合したボックスフィルタで行う（1 パス削減 + 中間 RT 不要）。
  タップ数は軸あたり 8 に制限してあるので、極端な縮小率でもシェーダが詰まらない。

## 2. 段階キャッシュ

`PipelineContext` が作業 RT 一式と前回実行時のシグネチャを保持する。`DetermineDirty()` が
**再実行が必要な最初のステージ**を返し、そこから後ろだけを走らせる。

| 変更したパラメータ | 再実行されるステージ | ディスパッチ数 |
|---|---|---|
| Strength / NormalMapType / Dither | Normal のみ | 1 |
| InputMode / DisableBevel | Composite 以降 | 2 |
| BevelRadius（縮小）/ ProfileType | Profile 以降 | 4 |
| BevelRadius（拡大） | JFA 以降 | 全部 |
| Threshold / InvertMask / テクスチャ | Binarize 以降 | 全部 |

これを成立させるための設計上の制約が 2 つある。

- `JFA_Distance` は**生の距離**を書く。`_BevelRadius` でクランプすると半径を変えるたびに
  距離場が無効になるため。シードが無い内部ピクセルも半径ではなく `DIST_FAR` を書く。
- `Binarize` を走らせたら `ctx.JfaValid = false` にする。ベベル無効時は JFA ブロックが
  丸ごとスキップされるので、ここで落とさないとベベルを再有効化したときに
  **古いマスクから作った距離場**が再利用される。

## 3. JFA

- 開始ステップは画像サイズではなく `NextPowerOfTwo(ceil(bevelRadius))`。
  伝播距離は `2*range - 1 >= radius` を満たすので、必要な帯では**全レンジ版と完全に同一の結果**になる
  （円マスクでの数値検証で最大差 0.000000 px）。2048px / 半径 15 で 12 パス → 6 パス。
- 末尾に `k=1` を 1 パス追加（JFA+1）。標準 JFA の誤判定ピクセルをほぼ潰す。
- キャッシュは `JfaRangeCached` を持ち、半径が**大きくなったときだけ**無効化する。

### サブピクセルシード

境界ピクセルはピクセル中心ではなく、グレー値がしきい値と交差する点を推定して置く。

1. **主推定**：`gray(p + t) = threshold` を 1 次で解く → `t = -grad * (gc - threshold) / |grad|²`
   微分は**暗い側への片側差分**を使う。中心差分はステップエッジで傾きが半分になり、
   境界を 0.5px 行き過ぎる。
2. **フォールバック**：`|grad|² ≈ 0`（4 近傍が平坦なのに斜め近傍だけ背景、
   ハードエッジや AA ランプが飽和している箇所で起きる）のときは、
   背景側 8 近傍への単位ベクトルの和の向きに 0.5px ずらす。

半径 80 の円マスクでの実測（帯域内の解析解との平均絶対誤差）：

| 入力 | 中心シード（旧） | 主推定のみ | 主推定+フォールバック（現行） |
|---|---|---|---|
| ハード二値 | 0.957 px | 0.894 px | **0.519 px** |
| AA 1px ランプ | 0.957 px | 0.282 px | **0.166 px** |
| AA 2px ランプ | 0.957 px | 0.008 px | **0.008 px** |
| 最大誤差 | 1.397 px | 1.397 px | **0.897 px** |

## 4. ブラーとプロファイル

分離可能ガウシアン 2 パス。`sigma = clamp(bevelRadius * 0.05, 0.6, 4)` と半径連動なので、
作業解像度が変わっても見た目の平滑度が変わらない（旧実装は固定 3×3 で、2048px では実質無効だった）。
プロファイルカーブは**ブラー後に 1 回だけ**評価する（旧実装は 9 タップそれぞれで `log`/`exp` を評価）。

## 5. カラースペース

プロジェクトが Linear の場合、sRGB インポートされたテクスチャは Load 時にリニアへ変換される。
`Binarize` はこれを `LinearToDisplay()` で表示空間に戻してから輝度・しきい値処理を行う
（`_InputIsLinear` は `GraphicsFormatUtility.IsSRGBFormat` から C# 側が決定）。

**破壊的変更**：旧実装はリニア値としきい値を比較していたため、`Threshold = 0.5` は
実質 sRGB 188/255 相当だった。移行時はしきい値の再調整が要る。

出力用 `normalRT` は **sRGB フラグ付きのまま**にしてある。コンピュートシェーダは UAV 経由で
生バイトを書き、`ReadPixels` も sRGB 同士の生コピーになるので PNG は素通しになる。
ここを Linear に変えるとエディタ表示と保存 PNG がずれるので触らないこと。

## 6. RenderTexture の扱い

- 旧実装は毎更新で 8 枚の RT を `new` して `Release()` するだけだった。`Release()` は GPU 面しか
  解放せず**ネイティブオブジェクトはリークする**。現行は `PipelineContext` が保持して使い回し、
  破棄は `Release()` + `DestroyImmediate()` の両方を行う。
  2048px で 1 更新あたり約 168MB の確保／解放が消えた。
- 表示される `Normal` RT のみ `useMipMap = true` + `FilterMode.Bilinear`。
  2048px を 250px の枠に Point フィルタで描くと激しくエイリアシングするため、
  解像度を上げるならこれは必須。ディスパッチ後に `GenerateMips()` を呼ぶ。
